# Vitalog

成人発症スティル病（AOSD）当事者本人のための、体調・服薬・生活負荷を記録するセルフトラッキングPWA。

詳しい背景・設計思想・全機能要件（F1〜F12）は [`docs/requirements.md`](./docs/requirements.md) を参照。

## このセッションで実装した範囲

- **F1: 毎日の体調記録** をフル実装（体温・体調スコア・関節痛・咽頭痛・気分スコア・落ち込み理由タグ・服薬記録・自由メモ・音声入力・筋肉痛/リンパ節腫れ/皮疹などの任意項目・後入力/スキップ）
- **F2: 服薬記録**（`/medications`）: 定期薬/頓服マスタの登録、減薬・増薬(テーパリング)履歴、Notification APIによるリマインダー（※アプリを開いているタブでのみ動作するフォアグラウンド通知。真のバックグラウンドPushにはService Worker+サーバー側のPush購読管理が必要なため今回のスコープ外）
- **F4: データ可視化**（`/trends`）: 体調/気分スコア・体温・睡眠時間のトレンドグラフ(依存ライブラリなしの自前SVG実装、ホバーで値を表示、7/30/90日/全期間フィルタ)。dataviz運用ガイドの検証済みカテゴリカルパレット(青/オレンジ)を使用
- **F9: スケジュール・負荷管理**: 負荷感(3段階)・活動タグ(カスタムタグ追加可)・睡眠時間を毎日の記録に統合
- **F10: 緊急時検出・受診推奨**: 高熱の持続＋普段と違う強い倦怠感、または検査値(フェリチン/血小板)の急変をルールベースで検知し、記録画面上部に警告バナーを表示。**診断ではなく受診推奨の一次スクリーニングであり、閾値は暫定値**であることを明記（`lib/emergencyCheck.ts`）。F12-4のライフステージ移行期間中は自動的に閾値を敏感化する
- **F3: 環境データ取得**: Open-Meteo(APIキー不要)から気温・気圧・湿度を自動取得。ブラウザのGeolocation APIで位置情報を1回だけ取得しlocalStorageに保存、以降は対象日に応じて現在値/過去データAPIを自動で使い分ける
- **F7: 医師向けレポート出力**（`/report`）: 期間別(7/30/90日/全期間)の統計サマリー(平均スコア・関節痛部位別頻度・服薬一覧・メモ等)を表示し、ブラウザの印刷機能でPDF保存できる
- **F8**: `types/vitalog.ts` の `SCHEMA_VERSION` と `lib/migrate.ts` によるデータバージョン管理・マイグレーション、JSON/CSVエクスポート、JSONからの復元、**Google Driveへのバックアップ**（`NEXT_PUBLIC_GOOGLE_CLIENT_ID`設定時のみ有効。appDataFolderスコープでこのアプリ専用の隠しフォルダにのみアクセス）（`/backup`）
- **F12-1: 仮説検証フレームワーク**（`/experiments`）: 仮説の登録・一覧。統計的な支持率算出はF5/F11(相関分析)実装後
- **F12-2: セルフA/Bテストログ**（`/experiments`）: 介入期間の宣言と、介入前の同じ日数分との体調スコア平均比較（厳密な統計検定ではなく簡易的な目安）
- **F12-4: ライフステージ移行監視モード**: 2027年4月前後90日間を要注意期間として自動フラグし、バナー表示とF10の閾値敏感化を行う（`lib/lifeStage.ts`、日付は要件変更時に直接書き換え）
- **F12-5: 健康×生産性相関記録**: 任意入力の成果実感スコア(1〜10)を毎日の記録に追加
- 自由メモの自動タグ付け（`POST /api/tag-memo`、Claude Haiku利用、`ANTHROPIC_API_KEY`未設定でも記録自体は問題なく動作）
- **写真ベースの自動記録(F1拡張)**: 服薬パッケージ/外用薬パッケージ/血液検査結果票の写真をVision対応LLM(既定はHaiku、`ANTHROPIC_VISION_MODEL`で変更可)に渡し構造化データを抽出。**抽出結果は必ず確認・編集画面(`components/PhotoCaptureButton.tsx`)を経てからDailyLogにマージ**され、無確認で自動保存されることはない。写真本体は既定では破棄し、ユーザーが明示的に選んだ場合のみIndexedDB(この端末のブラウザ内のみ)に保存する。抽出結果はDailyLogの頓服(`medications`, type: asNeeded)・新設の外用薬(`topicalMedications`)・検査値(`labs`、WBC/フェリチン/CRP/AST/ALT/血小板)にそれぞれ反映
- **F2拡張: 服薬管理の抜本改善**（`/medications`）:
  - 過去の処方箋・検査結果票を複数枚まとめてインポートし、書類の日付を対象日として既存の毎日の記録に(上書きせず)追記する一括インポート機能
  - 服薬管理に登録済みの定期薬は、毎日の記録画面でチェックボックス方式(既定: 服用済み)になり、手入力が不要に。頓服は従来通り手動追加
  - お薬手帳の写真から複数の薬・処方日をまとめて読み取り、現在の登録済み薬との差分(新規/用量変更/中止候補)を提示してから、確認したものだけ反映する差分更新機能
  - `lib/settings.ts`によりライフステージ移行日(F12-4)を`/settings`画面から変更可能に

F5/F6/F11(相関分析・アラート予測)、F12-3(年次振り返り)は未実装。要件定義書の設計思想通り、データ量に応じて段階解禁する前提の機能(30/90/365日〜)のため、実データが貯まってから着手する。`app/roadmap` に実装状況の一覧がある。

## 設計上の決定

- **サーバーレス・localStorage永続化**: 単一ユーザー・認証不要というスコープに対し、他アプリ（`aws-saa-study`等）と同様にクライアントサイドのみで完結させた。医療データそのものをリポジトリやサーバーに一切置かない方針とも合致する。
- **記録対象日(`targetDate`)と実入力時刻(`recordedAt`)を分離**: 「いつでも記録可能・後入力・スキップ可」という継続性最優先のUX方針を型レベルで表現している。
- **メモのLLMタグ付けは失敗しても記録を止めない**: API未設定・通信エラー時もsilentに失敗し、体調記録自体の入力体験を損なわない。
- **F9の項目は独立レコードにせず、DailyLogのフィールドとして統合**: 「1日の記録は1つ」というF1の設計をそのまま踏襲した方が、相関分析(F5/F11)の際にレコード結合の手間がなく扱いやすいと判断した。
- **F10の閾値はハードコードされた暫定値**: 山口基準等の一般的な目安（38℃の高熱、フェリチン500ng/mL等）を仮置きしている。F5/F11で個人のベースラインが学習できるようになれば、パーソナライズ閾値に置き換える前提。
- **緊急検出はローカルで即時判定**: サーバーへのデータ送信なしにブラウザ内で完結させ、オフラインでも動作する。
- **写真データはDailyLogの外に置く**: `lib/photoStore.ts` (IndexedDB)で写真を管理し、DailyLogには`sourcePhotoId`という参照IDだけを持たせる。これにより写真本体がJSON/CSVエクスポートやlocalStorageの記録データ本体に混入することが構造的にありえない。皮疹写真も当初はlocalStorageにdataURLとして直接埋め込んでいたが、容量制限(5〜10MB程度)によるQuotaExceededErrorのリスクがあったため、他の写真機能と同じIndexedDB方式に統一した。
- **写真からの抽出は確認必須、無確認保存は不可**: 特に検査値はF10の緊急検知に使われるため、LLMの誤読がそのまま記録される事態を型・UIの両方で構造的に防止している(`PhotoCaptureButton`はconfirm操作なしに状態を`reviewing`から先に進められない)。
- **F12-1/F12-2は「枠組みだけ」先に作る**: 支持率の統計算出や有意差検定はF5/F11(相関分析基盤)が前提になるため、今回はデータ構造とUI(登録・一覧・簡易比較)のみ実装し、統計エンジンは後回しにした。
- **Google Driveはappデータフォルダのみ**: `drive.appdata`スコープを使い、ユーザーの他のDriveファイルには一切アクセスしない設計。サーバーを経由せずブラウザ内でOAuthトークン取得からアップロードまで完結させる。
- **バックアップの上書きには必ず退避が挟まる**: JSONインポート・Google Drive復元とも、実行直前の状態を1世代だけlocalStorageに自動退避してから上書きする(`lib/storage.ts`の`importStoreFromJson`)。誤って古い/壊れたバックアップを復元しても、バックアップ画面の「直前の復元操作を取り消す」で戻せる。Google Drive側も単一ファイル上書きではなく日付付きファイル名で直近5世代を保持する。
- **緊急検出は「実際の今日」から見た直近14日以内の記録だけを見る**: 過去の処方箋・検査結果を後から一括インポートした際、それが記録全体の中で最新の日付だと、発病当初のような何年も前の重い数値を「現在の状態」として誤って警告してしまうバグがあった。`EMERGENCY_LOOKBACK_DAYS`で判定対象を直近14日に限定して修正した。
- **服薬管理は「チェック方式」を採用**: 定期薬は登録さえしておけば毎日の記録画面で薬品名・用量を再入力する必要がなく、チェックボックスのオン/オフだけで完結する。既定はチェック済み(服用した)とし、飲まなかった日だけ外す「例外ベース」の入力にすることで、長期継続のハードルを下げつつ、未服用の記録もあいまいにせず明示的に残す(`MedicationRecord.taken`)。
- **お薬手帳の差分更新は必ず確認を挟む**: 複数の薬・複数の受診日が並ぶお薬手帳を解析すると、抽出精度のブレが大きくなりやすい。新規/用量変更/中止候補を提示するだけに留め、実際の反映(特に中止)はユーザーが個別にチェックを入れるまで一切実行しない。

## セットアップ

```bash
npm install
npm run dev
```

`.env.local.example` を `.env.local` にコピーして使う。

- 自由メモの自動タグ付け・写真からの自動記録には `ANTHROPIC_API_KEY` が必要（未設定でも他機能は動作し、自動入力機能だけ手動入力にフォールバックする）
- Google Driveへのバックアップには `NEXT_PUBLIC_GOOGLE_CLIENT_ID` が必要。Google Cloud ConsoleでDrive APIを有効化し、OAuthクライアントID(ウェブアプリケーション)を発行して、承認済みのJavaScript生成元にデプロイ先URLと`http://localhost:3000`を登録する（未設定でも他機能は動作し、Driveバックアップだけ「未設定」表示になる）

## Vercelへのデプロイ

このリポジトリの他アプリと同様、Vercelプロジェクトの **Root Directory** を `vitalog` に設定してデプロイする。
